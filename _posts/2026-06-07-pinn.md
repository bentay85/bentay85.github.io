# Physics-Informed Neural Networks (PINNs)

Neural networks are great at spotting patterns in data, but show them something outside their training set and they confidently make things up - and can even violate basic conservation laws. Physics-Informed Neural Networks (PINNs) fix this by embedding the known governing physical laws directly into the network's loss function, so the solutions it learns have to obey physics.

### Core Mechanics

PINNs use the neural network as a universal function approximator while enforcing physical consistency:

* **Functional approximation.** The network acts as a continuous model, mapping independent variables (such as time, t, and space, x) to the physical state variables of the system.
* **Automatic differentiation.** Partial derivatives are computed using the chain rule via the framework's computational graph - PyTorch's autograd does this natively. This lets the network evaluate differential equations and initial/boundary conditions at arbitrary points in the domain, without traditional numerical discretization (finite differences or finite elements) and without mesh-generation constraints.
* **Composite loss.** To restrict the optimization search space to physically consistent states, the network's objective function is formulated as a composite loss:

```
Total Loss = Loss(data) + Loss(physics) + Loss(boundary)
```

* **Loss(data):** penalizes deviation from observed/empirical data points.
* **Loss(physics):** penalizes deviations from the governing differential equations evaluated at chosen collocation points.
* **Loss(boundary):** enforces boundary and initial conditions.

This regularization dramatically improves data efficiency and ensures robustness in data-scarce regimes.

### Model Problem: Mass-Spring-Damper System

To evaluate PINN performance, I model a classical mass-spring-damper system without external excitation. This system is governed by a second-order linear ordinary differential equation (ODE) derived from Newton's Second Law:

```
m * (d²x/dt²) + μ * (dx/dt) + k * x = 0
```

**Given parameters:**

* Mass (m) = 1.0 kg
* Damping coefficient (μ) = 4.0 Ns/m
* Spring stiffness (k) = 400.0 N/m

**Initial conditions:**

* Initial displacement: x(0) = 1.0 m
* Initial velocity: dx/dt(0) = 0.0 m/s

Substituting these physical parameters into the governing equation yields:

```
d²x/dt² + 4 * (dx/dt) + 400 * x = 0
```

This configuration describes an underdamped oscillator, which exhibits decaying harmonic motion - a much more meaningful curve for the neural network to fit.

### Analytical Reference Solution

To establish a baseline for verification, I calculate the exact analytical solution first. Details on the derivation can be found in this [link](https://math.libretexts.org/Courses/Cosumnes_River_College/Math_420%3A_Differential_Equations_(Breitenbach)/06%3A_Applications_of_Linear_Second_Order_Equations/6.02%3A_Spring-Mass_Problems_(With_Damping)). The characteristic equation is:

```
r² + 4*r + 400 = 0
```

Solving for the roots (r):

```
r = -2 ± i * sqrt(396)
r ≈ -2 ± 19.900 * i
```

This yields the attenuation factor (alpha) and damped natural frequency (omega_d):

```
alpha = 2.0
omega_d ≈ 19.900 rad/s
```

The general solution for an underdamped system is:

```
x(t) = e^(-alpha * t) * [A * cos(omega_d * t) + B * sin(omega_d * t)]
```

Applying the initial conditions:

1. **At t = 0, x(0) = 1.0:**

    ```
    x(0) = e^(0) * [A * cos(0) + B * sin(0)] = A
    A = 1.0
    ```

2. **At t = 0, dx/dt(0) = 0.0:**

    Differentiating x(t):

    ```
    dx/dt = -alpha * e^(-alpha * t) * [A * cos(omega_d * t) + B * sin(omega_d * t)]
          + e^(-alpha * t) * [-A * omega_d * sin(omega_d * t) + B * omega_d * cos(omega_d * t)]
    ```

    Evaluating at t = 0:

    ```
    0 = -alpha * A + B * omega_d
    B = (alpha * A) / omega_d
    B = (2.0 * 1.0) / 19.900 ≈ 0.10050
    ```

Expressing this in amplitude-phase form:

```
x(t) = C * e^(-alpha * t) * cos(omega_d * t - phi)
```

Where:

* Amplitude (C) = sqrt(A² + B²) = sqrt(1.0² + 0.10050²) ≈ 1.0050
* Phase angle (phi) = arctan(B / A) = arctan(0.10050 / 1.0) ≈ 0.10017 rad

This gives the final, exact analytical solution used for evaluating PINN accuracy:

```
x(t) = 1.0050 * e^(-2 * t) * cos(19.900 * t - 0.10017)
```

### Scripts

The python scripts that I used to explore PINNs can be found [here](https://github.com/bentay85/pinn).

1. **1_Forward_Euler.py:** Simulates the system using a state-space representation solved via the **Forward Euler** method. Compares numerical results directly against the analytical solution to check for accuracy. This script was written mainly to check how fast a direct simulation method would be for a simple 1D system like the mass-spring-damper system. This method solves much faster than a PINN, and for a forward solution of a simple system, such a method should be used instead of a PINN.

2. **2_pinn_simulate.py:** Uses a PINN to simulate the system. There is no training data - the boundary conditions and physics are used to propagate the loss through the network at each step. Main takeaways are as follows:

    * The tanh activation function is used as it is infinitely differentiable. For PINNs, we normally need to calculate the first and second differentials.
    * When defining the variables for time = 0s and the time vector where the physics error is penalised, `requires_grad=True` is set as we need to propagate the loss from these variables.
    * The mean squared error is used for both the initial condition loss and the physics loss. Since there is only 1 position and 1 velocity initial condition, the squared error is calculated.
    * The total loss is calculated as 5000 * (Sum of initial condition loss) + Physics Loss. 5000 is a hyperparameter that needs to be tuned to prevent the trivial solution of zero everywhere, which satisfies the physics loss, from being obtained.

3. **3_pinn_data.py:** Here we generate a noisy dataset which only spans the first 0.5s to check if the physics loss actually helps the model generalise to the time period where there is no data. We consider 2 loss terms, the data loss and the physics loss. The data loss is calculated as the mean squared error between the model's predictions and the noisy data. The total loss is calculated as 5000 * Data Loss + Physics Loss. 5000 is a hyperparameter that needs to be tuned to prevent the trivial solution of zero everywhere, which satisfies the physics loss, from being obtained.

4. **4_pinn_unknown_parameters.py:** Here we have an unknown parameter, the damping coefficient, which is randomly initialised. It is then added to the Adam optimiser and value optimised together with the neural network parameters. Number of steps was increased to 20,000 as this is a more complex problem where the physics is not fully defined and required more steps to converge. An additional graph of the value of C was plotted against epoch to visualise how it converged. PINNs lend themselves very naturally to solving for unknown parameters along with solving for the parameters of the neural network.
